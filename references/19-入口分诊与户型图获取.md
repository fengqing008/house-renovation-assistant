# 19 · 入口分诊与户型图获取

> 收到装修请求，**先分诊、再动手**。用一张三选项询问卡定下"信息来源"，避免无图硬编户型。
> 配套脚本：`scripts/entry_triage.py`（`--gen` 出卡 / `--parse` 解析 / `--search-query` 生成检索词 / `--verify` 面积核对）。

## 一、为什么先分诊

装修方案的质量，八成取决于"现状输入"。同一套 120㎡ 的房子，有没有真实户型图，出的是两套东西：有图 → 开间进深、承重墙、朝向、门窗都能落到实处；无图 → 尺寸只能标【待核】，方案会浮。

所以在既有六步工作流（S0 需求澄清 → S1 风格 → S2 现状 → …）**之前**，加一道 **S-1 入口分诊**：一句话问清信息来源，再决定用哪条路径。**只问一轮，不反复打断。**

## 二、入口三选项（询问卡）

技能收到装修请求后，先输出下面这张卡（`python3 scripts/entry_triage.py --gen`）：

```
请先告诉我你属于哪种情况（回复 1 / 2 / 3 即可）：

1️⃣ 我有小区信息
   请提供：小区名称 + 楼栋号 + 建筑面积（㎡）
   → 我会全网检索该小区该栋的公开户型图，基于真实户型做设计
   例：万象春天 3号楼 118㎡

2️⃣ 我有户型图 / 设计图
   直接把图发我（照片 / 截图 / PDF 均可）
   → 我识别图纸后基于原图做设计

3️⃣ 其他情况（说不准 / 暂无图 / 只想要个大概）
   → 我一步步问你（面积、几室几厅、风格偏好…），边问边出方案
```

**分支判定**（`--parse` 容错识别关键词）：

| 用户回复 | 命中路径 | 说明 |
|---------|---------|------|
| 1 / 一 / 含"小区""楼栋" | **A · 小区户型图全网检索** | 需齐：小区名称 + 楼栋号 + 建筑面积 |
| 2 / 二 / 含"户型图""设计图" | **B · 上传图识别设计** | 等用户发图 |
| 3 / 三 / 其他 / 无明确输入 | **C · 逐步询问** | 走原五维 + 问卷 |

> 只说"帮我装修"而没有其它信息 → 直接出卡；用户已随手发来户型图 → 直接判路径 B，不再多问。

## 三、路径 A · 小区户型图全网检索

### A1 检索词构造（`--search-query`）

按"精 → 中 → 宽"三档构造，**逐档检索直到命中**：

| 档位 | 检索词模板 |
|------|-----------|
| 精（逐栋/逐面积） | `{小区} {楼栋} 户型图`｜`{小区} {面积}㎡ 户型`｜`{小区} {楼栋} 平面图` |
| 中（小区级） | `{小区} 户型图`｜`{小区} 户型 面积`｜`{小区} 在售 户型` |
| 宽（片区/期数） | `{小区} 楼盘 户型`｜`{小区} 一期 户型`｜`{小区} 二手房 户型图` |

**检索工具**：`search`（`format=text` 找挂牌页/图文详情，`format=image` 找户型图本体）；贝壳/安居客/小红书等强反爬源，经 `agent-reach` 抓取。

### A2 来源可信度优先级

| 优先级 | 来源 | 可信度 | 备注 |
|--------|------|--------|------|
| 高 | 贝壳/安居客/链家 挂牌户型图（带面积标注） | 较准 | 可与用户面积交叉核 |
| 高 | 开发商/物业官方公示、楼书 | 高 | 权威优先 |
| 中 | 业主论坛、装修平台晒图 | 需核对 | 常带改动，注意是否为原始交付 |
| 低 | 自媒体转载、无来源图 | 仅参考 | 不得作为尺寸依据 |

### A3 真实性核验（三查）

1. **面积核**（`--verify`）：图注面积 vs 用户所给面积，偏差 **≤±5% 视为匹配**；±5%~±10% 提示可能相邻户型；**>±10% 不得作设计依据**。
2. **结构核**：与"几室几厅 + 朝向 + 大致形状"比对；明显不符则弃用。
3. **来源核**：记录来源链接、截图时间，写入"房屋现状档案"。

### A4 命中 / 未命中处置

| 情形 | 处置 |
|------|------|
| 命中且面积匹配 | 写入现状档案（户型/开间进深/承重墙/朝向/门窗），标"来源：公开检索，以实际测绘为准" → 进 S2 |
| 命中但面积不符 | 列 2–3 个候选户型让用户指认；>±10% 不得直接用（FM-16） |
| 全部未命中 | 明确告知"未检索到公开户型图"，**自动降级路径 C**，**不得臆测户型**（FM-15） |

## 四、路径 B · 上传图识别设计

1. 用户发图后，用 `fetch` 读取（照片/截图/PDF 均可）；
2. 提取：建筑面积、房间构成、开间进深、承重墙位置、朝向、门窗位置；
3. 图模糊/遮挡不可识别 → 请补传或转路径 C（FM-07）；
4. 精装交付标准图、或明显改过结构的图 → 与用户确认"是否按原图设计"；
5. 写入"房屋现状档案" → 进 S2。

## 五、路径 C · 逐步询问

- **第一轮**：补齐关键约束（建筑面积 / 所在城市 / 装修范围）——见"需求澄清"五维表；
- **第二轮**：跑 `questionnaire.py` 出 12 题风格问卷，`style_match.py` 判风格；
- 无图时按"房间清单 + 估算面积"采集，方案中所有尺寸标【待核】；
- **边问边出**：每轮给阶段小结，不让用户空等。

## 六、三路径汇合

三条路径最终**产出同一种产物**——**房屋现状档案**（V1 输入单），字段固定：

```
建筑面积 | 所在城市 | 几室几厅 | 开间进深 | 承重墙 | 朝向 | 门窗
| 来源（小区检索/上传图/问答估算）| 可信度（高/中/低）| 待核项清单
```

档案生成后统一汇入既有 **S2 现状识别 → S3 方案生成 → …**，后续流程完全一致。

## 七、合规红线

1. 户型图**仅作设计参考，不替代实测**；成果须注"以实际测绘 / 物业确认为准"。
2. **不伪造户型、不臆造精确尺寸**——未核实一律标【待核】。
3. 引用公开图**注明来源**，不声称拥有版权；不越权下载/传播涉密图纸。
4. 涉及拆改必提示核实结构并按规定报备（对齐主红线）。

## 八、失败模式（见 `08`）

- **FM-15** 无图臆测户型 → 明确告知未检索到，降级路径 C；
- **FM-16** 户型图面积不符仍采用 → 列候选指认或弃用；
- **FM-17** 户型图当实测依据 → 补来源与"以实际测绘为准"声明。

## 九、一句话流程

```
收到装修请求 → 出三选项卡（S-1）
   ├─ ①小区+楼栋+面积 → 全网检索户型图 → 面积核(±5%) → 现状档案
   ├─ ②上传户型图/设计图 → 识别 → 现状档案
   └─ ③其他 → 逐步询问（五维+问卷）→ 现状档案
        └──────────────→ 汇入 S2 现状识别 → S3 方案 → …（原流程）
```
